# SF_Gastronomicon v1.1.6 — maintained Slimefun Legacy/Paper API compatibility

New standalone addon release, source-distinct from the immutable [v1.1.5](https://github.com/wickidcow/SF_Gastronomicon/releases/tag/v1.1.5). This version packages the Gastronomicon production updates already merged after v1.1.5 together with verified Java 21 build and release safeguards.

## Changes since v1.1.5

- Replace deprecated Slimefun `BlockStorage` calls in the automatic **Electric Kitchen** and **Fishing Net**, manual workstations, seeds, trees, crop and hunting listeners, and SlimeHUD integration with the maintained Slimefun Legacy block-data controller. The adapter preserves existing Slimefun IDs and accesses the current block record, its named custom data keys and existing block menu instead of generating replacement IDs or rewriting saved items.
- Read and write **Multi Stove** temperature using the existing `TEMPERATURE_KEY`; retain current selected temperatures rather than change their names or stored schema.
- Use the modern long-valued energy API for **Refrigerator** checks and consumption, avoiding an `int` cast of existing charges.
- Modernize item/potion type access and legacy/hex color formatting for guide and workstation displays.
- Update Maven/Java 21 build dependencies and validate Paper 1.21.11, 26.2 and stable 26.3 API compatibility. The raw plugin JAR preserves its existing `Gastronomicon` entrypoint.

## Integrity and release requirements

This candidate must pass the exact-head source and universal shaded-JAR build, Java 21 bytecode and plugin.yml version checks on all three Paper API lanes. The master publisher is create-only: new tag `v1.1.6` may be created only after a successful push to the exact current `master` SHA; a prior tag or release cannot be overwritten, retargeted or republished. It downloads the official raw JAR and rechecks its SHA-256.

**This build does not itself prove live historical world storage parity or Folia region ownership.** Source compilation and synthetic raw-JAR tests cannot simulate old AlbionMC saved inventories, machine operations or protected-region event routing. Do not describe those combinations as native-tested.

## Recommended backed-up staging acceptance

1. Stop the server, back up worlds and existing Slimefun / Gastronomicon data, and replace the previous JAR with only `SF_Gastronomicon1.1.6.jar`.
2. Load **existing saved** Electric Kitchen, Fishing Net, Multi Stove, Refrigerator, Fermenter and Hunting Trap blocks. Compare saved IDs, block menus, custom data keys, energy, temperature, and all input/output quantities before and after two restarts.
3. Craft one recipe and a full-batch recipe in each applicable machine. Verify item count conservation, correct electricity use, no double drops on break and no dropped output when menus are full.
4. Test fruiting seeds, duplicate seeds, trees/crops and existing WorldGuard-protected farms; confirm harvest/break behavior and metadata match the prior version.
5. Check guide text, potion labels, SlimeHUD and custom food colors. Report any historical-item mismatch for a later, narrowly scoped fix.

No automatic historical item migration, Doctor rewrite, stored quantity reset or unprompted world conversion is introduced by the release metadata. v1.1.5 assets remain immutable. Slimefun-Legacy core, its v81 ZIP, and SlimefunUnified are maintained separately and are not modified here.
